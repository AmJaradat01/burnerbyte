## Worker Manager

The API server runs a worker manager that schedules 7 periodic jobs. Each runs at its interval (most configurable, two fixed) and is gracefully stopped on shutdown.

## Jobs

### Cleanup

**Interval:** `workers.cleanup_interval` (default: 5m)

Removes expired inboxes and their emails/attachments (including S3 objects), expired sessions, and expired password reset tokens.

### DNS Recheck

**Interval:** `workers.dns_recheck_interval` (default: 1h)

Re-verifies MX and TXT DNS records for all domains that aren't fully verified.

### Webhook Retry

**Interval:** `workers.webhook_retry_interval` (default: 1m)

Re-attempts webhook deliveries still pending retry, and periodically resets a webhook's failure count so one that hit its retry limit recovers on the next event. (Per-delivery retries use exponential backoff of 0s, 1s, 5s, 25s, applied inline by the dispatcher.)

### Reconciler

**Interval:** `workers.reconciler_interval` (default: 1m)

Synchronizes Redis inbox routing cache with PostgreSQL. Ensures active inboxes have corresponding Redis entries and expired inboxes are removed.

### Analytics

**Interval:** `workers.analytics_interval` (default: 5m)

Pre-computes analytics aggregates and caches them in Redis with a configurable TTL (`defaults.analytics_cache_ttl`, default: 2h).

### Invite Expiry

**Interval:** 24h (fixed)

Expires pending organization invitations past their expiry and notifies the relevant admins.

### Admin Stats

**Interval:** 10s (fixed)

Pushes live platform counts (emails, inboxes, domains, users, teams, storage) to the admin-stats WebSocket hub for the system-admin dashboard.

## Configuration

```yaml
workers:
  dns_recheck_interval: 1h
  cleanup_interval: 5m
  webhook_retry_interval: 1m
  reconciler_interval: 1m
  analytics_interval: 5m
  # invite_expiry (24h) and admin_stats (10s) run at fixed, non-configurable intervals
```
