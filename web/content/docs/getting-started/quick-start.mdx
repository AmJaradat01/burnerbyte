## Start the Servers

Open two terminals:

```bash title="Terminal 1 — API Server"
make run-api
```

```bash title="Terminal 2 — Frontend"
cd web && pnpm dev
```

The API server starts on port 8080 and the frontend on port 3000.

<Callout type="info">
The SMTP server (`make run-smtp`) is optional for initial setup. Start it when you're ready to receive real emails.
</Callout>


<Callout type="warn">
This assumes you have already run through [Installation](/docs/getting-started/installation)
— infrastructure up and `.env` in place. On a clean checkout with no `.env` and
no `config.yaml` the API has no database URL, so it boots the
[first-run installer](/docs/getting-started/installation#first-run-web-installer)
instead: the log prints a one-time `http://<host>:8080/install?token=...` URL and
every other path answers `503`.
</Callout>

## Setup Wizard

Navigate to [http://localhost:3000](http://localhost:3000). On first launch, you'll be redirected to the setup wizard which guides you through:

1. **Platform Owner** — Create the admin account (becomes system admin)
2. **Organization** — Name your org (e.g., "My Company")
3. **Outbound SMTP** — Configure email sending (for invites, password resets). You can use services like Mailgun, SendGrid, or your own SMTP server
4. **Domain** — Add your first domain (e.g., `test.example.com`). You'll need to configure DNS records for this domain
5. **Team** *(optional)* — Create a team and assign the domain to it
6. **Branding** *(optional)* — Set org logo and footer text
7. **Invites** *(optional)* — Invite team members via email

<Callout type="info">
After setup, any user who registers but has no organization is automatically redirected to `/onboarding` to create or join one. This is server-authoritative and cannot be dismissed. System admins are exempt — they can manage the platform (roles, SSO, system settings) without belonging to an org.
</Callout>

## Create Your First Inbox

After setup:

1. Select your team from the sidebar dropdown
2. Navigate to **Inboxes**
3. Click **Create inbox**
4. Choose a domain, optionally set an alias, and pick a TTL
5. Your temporary email address is ready — copy it and start receiving mail

## Receive an Email

Send a test email to your new inbox address. If the SMTP server is running and DNS is configured:

```bash
# Quick test with swaks (install via brew/apt)
swaks --to your-alias@test.example.com --server localhost:2525
```

The email appears in real-time via WebSocket — no page refresh needed.
